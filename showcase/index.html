01 · Where we started

A promising demo that couldn't survive reality

What: a Next.js 14 + Supabase Postgres + Razorpay codebase with a control-room dashboard, webhook receiver, rule-based diagnosis, recovery links and reconciliation. Why it wasn't enough: it ran on global test keys, faked success when Razorpay errored, had no auth, no multi-tenancy, and its database migration was 8 tables behind the code. No merchant could have used it — so we rebuilt it into something one could.

Stack

Next.js 14 · Supabase PG 17 · Drizzle · Vercel

TypeScript throughout, Tailwind UI, postgres driver with pooled connections, Vercel Cron driving the agent.

Money rails

Razorpay test → live path

HMAC webhooks, canonical payment state machine, idempotent recovery payment links with 60-minute expiry.

AI core

Deterministic diagnosis + autopilot

Rule engine with confidence, facts and guardrails — then an autonomous agent that acts inside merchant-set bounds.

02 · The backend audit

We read every file before writing a line

How: full read of all app/api/**, lib/**, db/schema.ts, migrations and scripts, plus tsc, env-presence checks and a migration-vs-schema diff. Why first: tsc passed — proving the bugs were logic, data and security holes no compiler would catch. Findings shipped as BACKEND_AUDIT.md + BACKEND_AUDIT.html in the repo: 8 critical, 10 high, 14 medium.

P0 · Data loss

Migration 8 tables behind the code

Settlements, recon, audit, eval and 4 more tables existed in code but not in SQL — any fresh database crashed on first use.

Why it mattered: the #1 production killer. Fixed by generating migration 0001 and applying it to live Supabase.
P0 · Money truth

Recovery links lied on SDK failure

Any Razorpay error returned success:true with a fabricated URL and marked the case resolved.

Why it mattered: fake revenue, dead customer links. Now failures stay proposed, return 502, cases stay open.
P0 · Safety

Batch jobs could auto-charge risk blocks

The batch executor processed every open case — including fraud blocks that must never auto-retry — with no cap and no auth.

Why it mattered: policy violation by design. Now allowlisted, capped at 25, admin-gated.
P0 · Blast radius

One click flipped every merchant to test mode

The connector self-test ran an unscoped UPDATE merchants SET mode='test' — plus logged raw key material.

Why it mattered: a demo button could take live merchants offline. Now single-row, masked logs.
P0 · Silent corruption

Missing DATABASE_URL fell back to localhost

A misconfigured deploy would silently read/write the wrong database instead of failing.

Why it mattered: invisible data split. Now fail-fast in production with host logging.
P0 · Open doors

Zero auth + open demo seeders in prod

Every mutating API accepted anonymous calls with free-text approved_by; anyone could flood prod with fake orders.

Why it mattered: audit spoofing + DB spam. Now middleware.ts + per-route gates (ADMIN_SECRET, CRON_SECRET).
03 · How we fixed it

Surgery, slice by slice — verified after each

Every fix kept tsc + next build green and ended with a live-database check. Highlights:

Idempotency

Check-then-insert → ON CONFLICT

Recovery, orders, attempts and recon upserts are race-safe; concurrent retries converge on one row instead of 500s or duplicates.

lib/connectors/razorpay.ts · lib/domain/normalizer.ts · reconciliation.ts
State machine

Terminal states can never regress

captured → failed is rejected; failed → captured (late success) allowed; known states never overwritten by unknown.

lib/domain/normalizer.ts → isAllowedTransition
Money math

Per-currency SQL aggregation

Dashboard sums moved into SQL GROUP BY currency — no more adding USD cents to INR paise behind one $ sign.

app/api/dashboard/summary/route.ts
Scale

Pagination + indexes everywhere

Case list went from full-table-scan + JS grouping to keyset pages with 15+ new indexes and uniqueness constraints.

db/schema.ts · migration 0001
Honesty

Audit holes are now visible

The logger returned a fake id:"error-log" row on failure. Now it returns null, logs an AUDIT HOLE, and JSON parsing never 500s a page.

lib/domain/audit.ts · app/api/audit/route.ts
Taxonomy

One failure language

Normalizer and AI engine diverged (issuer_decline vs customer_action…). Unified on the diagnose taxonomy so filters, eval and autopilot agree.

lib/domain/normalizer.ts · lib/ai/diagnose.ts

05 · Autonomous AI with guardrails

An agent merchants can bound — and therefore trust

Why autonomy this way: the moat isn't acting fast, it's acting safely. Autopilot is disabled by default; merchants opt in per-policy. The 03:00 UTC Vercel Cron runs it daily (Hobby-plan maximum; */15 on Pro).

Allowlist

Only safe categories

Customer-action + transient by default. Validation strips risk/config/unknown — the API refuses risk-only policies.

Caps

Amount, count, confidence

Per-order cap, max 50 actions/run, minimum confidence floor. Above any line → human.

Hygiene

Late captures auto-resolve

Orders that actually got paid are resolved with no link sent — a link for a paid order is never created.

Full sweep

Recon + expiry + replay

Each run reconciles the ledger, expires dead links, replays missed webhooks, and files a report in audit.

Brief

Copilot oversight

24h activity, 7-day recovery rate, anomaly flags for spikes, risk elevation and backlog growth.

Proof

Skips are audited too

Every skipped case records its reason (above_amount_cap, low_confidence_needs_human…) — oversight you can read.

06 · Real-world wiring

Five reasons nobody could use it — closed

Was

One global test key, zero onboarding

Now POST /api/merchants onboards with AES-256-GCM encrypted keys; webhooks route by account_id to each merchant's own secret.

Was

Links couldn't finish the money loop

Now capture webhooks match link IDs exactly → link paid, case resolved as paid, expiry swept, support packet tells paid/expired/pending truth.

Was

Nobody got told anything

Now a durable notifications outbox alerts merchants on case-open, link-created and link-paid — queued honestly without a destination.

Was

Missed webhooks stayed missed

Now the processor is replayable; a sweeper endpoint plus every agent run replays stale events idempotently.

Was

One secret for all merchants

Now per-merchant HMAC verification with global fallback; MASTER_KEY enforced for credential writes.

Bonus honesty

The smoke suite caught a real bug

Envelope parsing misaligned the AES IV — found by our own roundtrip test pre-commit, fixed, 5/5 green. Tests that catch things are the point.

07 · Judge sandbox

Zero login. Zero real money. Full loop.

Why a sandbox, not test keys: placeholder keys fail honestly (by design), which looks broken to a visitor. So DEMO_MODE forces a simulated gateway: deterministic demo checkouts served by the app itself, rate-limited public endpoints, power routes still key-locked. Verified live: seed → diagnose → link → pay → resolved + link paid, plus policy-ON → agent auto-recovery in one run.

Why this order of work?

Audit → fix → verify → deploy → autonomy → real-world wiring → demo. Each phase ended green before the next began, so at no point was the product half-broken. The demo sandbox came last deliberately — a tour of a lying product would have been theater; this one tours honest machinery.
