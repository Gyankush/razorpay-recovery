P0 Fix these 8 first

1 · Migration drift — DB will crash. drizzle/0000_fluffy_loki.sql vs db/schema.ts. Missing customers, diagnoses, payment_links, settlements, recon_items, audit_logs, eval_cases + columns.
Fix: npm run db:generate → review SQL → npm run db:push on staging → verify 13 tables → commit migration + CI drizzle-kit check.
2 · Recovery links lie on SDK failure. lib/connectors/razorpay.ts:73-102 fabricates https://rzp.io/i/plink_test_… and marks case resolved.
Fix: return success:false / HTTP 502, keep case open, store error in resultJson. Only resolve on verified payment.captured.
3 · Batch recovery hits risk blocks. app/api/recovery-runs/route.ts:18-32 processes all open cases, uncapped max_batch_size.
Fix: allowlist send_alternate_payment_link minus risk_block, clamp batch ≤25, deterministic idempotency keys, admin auth.
4 · Connector test mass-updates merchants + leaks key. app/api/connectors/razorpay/test/route.ts:44,52 — update(merchants).set({mode:"test"}) with no WHERE; raw keyId in audit.
Fix: update by id only; mask keys in logs.
5 · Silent localhost DB fallback. db/index.ts:11-13, drizzle.config.ts:13-15.
Fix: throw in production when DATABASE_URL missing; log host (not password) on boot.
6 · Demo seeds open in prod. app/api/demo/scenarios/[name]/route.ts.
Fix: 403 in production unless admin secret; preferably delete route before launch.
7 · payment_links never written. Schema exists, zero inserts; support packet fabricates URL.
Fix: transactional insert of recoveryActions + paymentLinks; packet reads stored URL; enforce expiry.
8 · No authN/Z. All mutating routes trust approved_by/operator from body.
Fix: middleware.ts session or x-admin-secret; propagate server-side actor to audit.
